# Формат истории: версии 1–3

JSON хранится в UTF-8. Неизвестные поля и неизвестные значения перечислений отклоняются.
Встроенные сценарии перечислены в `shared/src/commonMain/composeResources/files/catalog.json`: `story.json` и `stories/letter-at-dawn.json`. Правила каталога и проверка всех ресурсов: [authoring.md](authoring.md).

## Версия

Поддерживаются версии 1, 2 и 3. Отсутствие schemaVersion означает версию 1. Для мировых координат и наведения камеры на персонажа нужна версия не ниже 2; для переменных, эффектов выбора, аудио и настройки вариантов героини — версия 3. Старые истории работают с экранными позициями LEFT/CENTER/RIGHT. Другие версии отклоняются; автоматической миграции нет.

## Версия 3: последствия выборов

Корневой `initialVariables` объявляет переменные и их начальные значения Int, например `"initialVariables": { "trust": 0, "clue": 0 }`. Имена не должны быть пустыми. В версии 3 ссылки из условий и эффектов обязаны указывать объявленную переменную; опечатки блокируют загрузку с указанием узла и выбора.

```json
{
  "id": "help",
  "text": "Помочь с ремонтом",
  "targetNodeId": "after_help",
  "conditions": { "trust": 0 },
  "effects": { "set": { "clue": 1 }, "add": { "trust": 1 } },
  "unavailableReason": "Сначала нужно заслужить доверие.",
  "hideWhenUnavailable": false
}
```

Порядок: проверить все условия по текущему состоянию → проверить целевой узел → применить все `set`, затем все `add` → перейти. При совпадении имени в set и add прибавление идёт к присвоенному значению. Отрицательные значения допустимы. Переполнение Int не допускается: такой выбор недоступен, состояние не меняется. Линейный переход переменные не меняет. Эффекты выполняются при каждом успешном выборе, в том числе при повторном входе и переходе в тот же узел. Сам показ страницы эффектов не вызывает.

По умолчанию недоступная кнопка видна, отключена и сопровождается `unavailableReason` либо общим пояснением. Непустое пояснение поддерживает `{{playerName}}`. При `hideWhenUnavailable: true` недоступный вариант скрыт. Если все варианты недоступны, показаны сообщение и возврат в меню, а не финал. Предусматривайте безусловный выход: общий валидатор не доказывает отсутствие тупиков с учётом переменных. Host-тесты встроенной истории проверяют доступность продолжения на всех её маршрутах.

Автосохранение восстанавливает переменные воспроизведением маршрута от initialVariables. Повторное продолжение не удваивает эффекты; debug-отмена выбора отменяет и его последствия. Редакционные изменения названия, описания, имён, реплик и подписей выборов совместимы с сохранением. Изменения поведения, графа, ресурсов и остальных полей требуют новой игры; детали в [progress.md](progress.md).

## Версия 2: сцена и камера в одном пространстве

StageCharacter поддерживает `worldX` (от 0 до 1, по умолчанию null) и `groundY` (от 0 до 1, по умолчанию 0.92). Это центр спрайта по горизонтали и линия стоп в координатах фонового изображения. Высота мирового спрайта — 72% высоты фона, умноженные на scale. При worldX=null остаётся экранная постановка; position игнорируется, если задан worldX.

CameraView поддерживает `targetCharacterId`. Например, `"camera": {"targetCharacterId": "mira"}` переводит камеру к текущему worldX Миры. Поле имеет приоритет над focusX. Герой должен существовать, иметь спрайт, worldX и visible=true на всех маршрутах до узла. Проверяются и унаследованные составы сцены, и развилки. cameraStart тоже поддерживает targetCharacterId.

```json
{
  "stageCharacters": [
    {"characterId": "mira", "worldX": 0.32, "groundY": 0.9},
    {"characterId": "lev", "worldX": 0.68, "groundY": 0.9}
  ],
  "camera": {"targetCharacterId": "mira"},
  "cameraDurationMs": 1100
}
```

В следующем узле достаточно сменить targetCharacterId на lev: состав наследуется, персонажи стоят на месте, фон и спрайты перемещаются одним преобразованием камеры. Цель переоценивается при входе в узел. Если персонаж скрывается или убирается, переключите камеру на другого героя или числовой focusX.

Спрайты рисуются с прозрачностью, снизу вверх по groundY. FADE применяется к фону и мировым спрайтам вместе. При стандартном размере текста окно сцены занимает 62% области чтения, диалог — 38%; увеличение текста расширяет диалог вплоть до 50%. Длинный текст прокручивается. Длина реплики не вызывает скачка масштаба. У края изображения камера ограничивается границами; на широком экране, где фон помещается целиком, панорамирование может быть незаметно.

Остальные поля и правила ниже общие для всех версий, если не указано иное.

## Корень StoryScript

Появление персонажа в диалоге настраивается общим для истории блоком:

```json
"characterAppearance": {
  "enabled": true,
  "durationMs": 400,
  "slideDistance": 1.0,
  "fade": true
}
```

Это значения по умолчанию, блок необязателен во всех версиях. `enabled: false` или `durationMs: 0` показывают персонажа сразу. Длительность задаётся в миллисекундах (неотрицательное целое), `slideDistance` — доля ширины окна сцены от 0 до 1; 1 означает выезд из-за края, 0 оставляет только фейд. `fade: false` отключает плавное проявление.

Для экранной постановки (без `worldX`) позиция берётся из `stageCharacters.position` говорящего персонажа; при мировой постановке или без записи главный герой располагается справа, остальные — слева. LEFT въезжает слева, RIGHT — справа, CENTER появляется без горизонтального движения. Анимация запускается при появлении нового говорящего, смене сцены или позиции, но не повторяется на последовательных репликах того же персонажа. Настройка относится к персонажу переднего плана в диалоге.

| Поле | Значение |
| --- | --- |
| `schemaVersion` | Целое, 1, 2 или 3; по умолчанию 1 |
| `initialVariables` | Начальные значения переменных Int, по умолчанию {}; версия 3 |
| `playerOptions` | Допустимые внешности и одежда героини в порядке показа; настройка требует версии 3 |
| `id`, `title` | Обязательные непустые строки |
| `description` | Необязательное описание, по умолчанию null |
| `characters` | Массив персонажей, по умолчанию пустой |
| `startSceneId`, `startNodeId` | Обязательная ссылка на существующий начальный узел |
| `scenes` | Объект: ключ — ID сцены, значение — Scene |

ID сцены и узла должны совпадать с ключами объектов и не быть пустыми. ID узла уникален внутри сцены; разные сцены могут иметь одинаковые ID узлов. ID персонажа уникален во всей истории.

## Персонаж и сцена

Character: обязательные непустые `id`, `name`; необязательный `spriteResource` (по умолчанию null). Рассказчику изображение не требуется.

Scene: обязательные `id`, `backgroundResource`; `nodes` — объект узлов, по умолчанию пустой. Пустая сцена допустима, если никто не ссылается на её узлы. Циклы и возвраты разрешены.

Пути отсчитываются от `composeResources`, начинаются с `files/`, используют `/` и не содержат пустых сегментов, `.` или `..`. Например: `files/scenes/forest.png`.
Все фоны и указанные спрайты проверяются до старта, включая невыбранные ветки. Отсутствующее или повреждённое изображение блокирует запуск с указанием пути.

## Узел DialogueNode

Обязательные поля: `id`, `characterId`, `text`. Персонаж должен существовать в корневом списке.

| Поле | Поведение |
| --- | --- |
| `choices` | Варианты выбора; отсутствие/null/[] означают отсутствие выбора |
| `nextNodeId` | Следующий узел для кнопки «Далее» |
| `nextSceneId` | Сцена следующего узла; отсутствие/null означает текущую |
| `nextSceneStartEffect` | `NONE` или `FADE`; по умолчанию без эффекта |
| `camera` | Целевая камера; правила наследования ниже |
| `cameraStart` | Явная начальная камера именно для этого узла |
| `cameraDurationMs` | Целое от 0 до 2147483647; по умолчанию 700 мс |
| `stageCharacters` | Полный состав персонажей; правила ниже |

Нельзя совмещать непустой `choices` и `nextNodeId`. `nextSceneId` и `nextSceneStartEffect` требуют `nextNodeId`. Если нет выбора и `nextNodeId`, узел завершает историю.

## Выбор Choice

Обязательные поля: непустые `id`, `text` и `targetNodeId`. ID уникален среди вариантов одного узла.

- `targetSceneId`: целевая сцена; отсутствие/null означает текущую.
- `targetSceneStartEffect`: `NONE` или `FADE`, применяется только при смене сцены.
- `conditions`: объект `имяПеременной: минимальноеЦелоеЗначение`. Все условия должны выполняться; отсутствующая переменная равна 0. Отсутствие/null/пустой объект означает отсутствие ограничений.

В версиях 1 и 2 переменные не меняются, отсутствующая переменная по-прежнему равна 0. В версии 3 доступны initialVariables и effects, описанные выше. Движок и UI используют одну проверку доступности; недоступный выбор не меняет состояние, журнал или сохранение.

## Камера и эффекты

CameraView содержит `focusX`: конечное число от 0 до 1, по умолчанию 0.5. `0` — левый край, `0.5` — центр, `1` — правый край. В версии 2 также доступен targetCharacterId. Полей zoom и focusY нет.

- Новая сцена сбрасывает камеру в центр, затем применяет `camera` входного узла.
- Внутри сцены отсутствие/null `camera` сохраняет предыдущую цель.
- `cameraStart` задаёт начало движения к цели за `cameraDurationMs`, включая первый узел сцены.
- Без `cameraStart` внутри сцены движение продолжается с текущей отображаемой позиции; новая сцена сразу показывает цель.
- Длительность 0 означает мгновенную установку цели. Начало и длительность не наследуются.

Фон масштабируется по высоте. Камера двигает фон и мировые спрайты; экранные спрайты остаются на месте. Если фон уже области отображения, он центрируется и панорамирование незаметно. Для проверки используйте портретную ориентацию с широким фоном. Координаты у краёв ограничиваются, чтобы не показывать пустую область.

`FADE` — появление нового фона и мировых спрайтов за 500 мс, не перекрёстное растворение сцен. Диалог и экранные спрайты в эффект не входят. Внутри той же сцены эффект игнорируется.

## Персонажи на экране

StageCharacter:

- `characterId` — обязательная ссылка на персонажа;
- `position` — `LEFT`, `CENTER`, `RIGHT`; по умолчанию `CENTER`;
- `scale` — положительное конечное число, по умолчанию 1;
- `visible` — по умолчанию true.

В одном списке персонаж не повторяется. Без `spriteResource` персонаж не рисуется. Базовая высота спрайта — 55% области сцены; scale умножает её. Появление занимает 400 мс. Смена позиции сопровождается повторным появлением, не перемещением по траектории.

Правила `stageCharacters`:

1. Новая сцена очищает предыдущий состав.
2. Отсутствие/null внутри сцены сохраняет предыдущий состав.
3. `[]` явно убирает всех.
4. Непустой список полностью заменяет состав.
5. `visible: false` скрывает персонажа; скрытое состояние наследуется вместе со списком.

## Минимальный пример

```json
{
  "schemaVersion": 1,
  "id": "example",
  "title": "Первый свет",
  "characters": [{ "id": "narrator", "name": "Рассказчик" }],
  "startSceneId": "forest",
  "startNodeId": "start",
  "scenes": {
    "forest": {
      "id": "forest",
      "backgroundResource": "files/scenes/forest.png",
      "nodes": {
        "start": {
          "id": "start",
          "characterId": "narrator",
          "text": "На краю леса забрезжил свет.",
          "cameraStart": { "focusX": 0.1 },
          "camera": { "focusX": 0.9 },
          "cameraDurationMs": 2500,
          "stageCharacters": []
        }
      }
    }
  }
}
```

Валидация охватывает весь граф, включая недостижимые ветки. Достижимость всех узлов и наличие финала не обязательны для формата: циклические истории допустимы. Встроенная тестовая история дополнительно проверяется host-тестами на достижимость и наличие концовок.

### Персонализация реплик

Идентификатор говорящего `protagonist` зарезервирован для созданной игроком героини. Её имя и портрет берутся из `StoryProgress.playerCharacter`. Токен `{{playerName}}` поддерживается в `DialogueNode.text`, `Choice.text` и `Choice.unavailableReason`, а также отображается подставленным в журнале. Имя вставляется буквально, без склонения и повторного разбора шаблонов. Без персонажа используется имя `protagonist` из списка `characters`, по умолчанию «Вы». Токен не применяется к идентификаторам, путям ресурсов и условиям.

## Версия 3: аудио и варианты героини

Сцена может содержать `"audio": { "music": "files/audio/theme.mp3", "ambience": "files/audio/sea.wav" }`. Оба поля необязательны; отсутствие или null означает тишину соответствующего канала. Поддерживаются WAV, MP3 и M4A под `files/audio/`. Одинаковый путь продолжает воспроизведение между узлами и сценами, новый заменяет канал. Файлы проверяются до открытия; ошибки проигрывателя показываются без блокировки чтения. Наружные сцены демо используют `sea.wav`. Подробнее: [audio.md](audio.md).

Корневой блок ограничивает и упорядочивает встроенные варианты:

```json
"playerOptions": {
  "appearances": ["DARK_HAIR", "RED_HAIR"],
  "outfits": ["COAT", "SWEATER"]
}
```

Допустимые внешности: `LIGHT_HAIR`, `DARK_HAIR`, `RED_HAIR`; одежда: `JACKET`, `SWEATER`, `COAT`. Списки должны быть непустыми и без повторов. По умолчанию доступны все три внешности и все три наряда; этот стандартный набор совместим со старыми версиями. Это выбор из общих атласов, а не произвольные ресурсы портретов. Подробнее: [character-creation.md](character-creation.md).

Настройки читателя хранятся вне сценария: масштаб текста и уменьшение анимации не изменяют авторский JSON или совместимость прохождения. См. [reading-settings.md](reading-settings.md).

### Эмоциональный портрет говорящего (версия 3)

Необязательное поле узла `speakerSpriteResource` задаёт изображение NPC только на текущей странице:

```json
"speakerSpriteResource": "files/characters/ilya-worried.png"
```

Без поля/при `null` используется `Character.spriteResource`; значение не наследуется следующей страницей. Имя и идентификатор говорящего остаются прежними. Ресурс входит в общую проверку путей и загрузки изображений. Для `protagonist` поле запрещено: её образ определяется персональным персонажем. Форматы 1 и 2 поле не допускают. Новый читатель принимает прежние сценарии без изменений; старые версии приложения не обязаны понимать новое поле. Прогресс сохраняет узел и снимок сценария, поэтому эмоция восстанавливается вместе с текущей страницей.
