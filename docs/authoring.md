# Проверка сценариев перед публикацией

Каталог `shared/src/commonMain/composeResources/files/catalog.json` перечисляет истории по `id` и пути `resource`. Идентификатор внутри сценария должен совпадать с записью каталога. Добавьте сценарий и его ресурсы в `composeResources`, затем запустите из корня проекта:

```shell
./gradlew :shared:testAndroidHostTest --tests '*StoryCatalogAssetsTest' --rerun-tasks
```

В Windows используйте `gradlew.bat`. Флаг `--rerun-tasks` гарантирует повторную проверку при редактировании ресурсов. Результат и напечатанный отчёт доступны в `shared/build/reports/tests/testAndroidHostTest/index.html` (страница тестового класса, Standard output). Для вывода журнала в терминал можно добавить `--info`.

Проверка читает каждую историю каталога штатным парсером, проверяет идентификаторы и структуру, существование и декодирование изображений, допустимые пути аудио и заголовки WAV/MP3/M4A. Заголовок аудио не заменяет прослушивание на Android и iOS.

Общая чистая функция `analyzeStory(StoryScript)` возвращает число узлов, финалы, недостижимые узлы, узлы только с условными выборами, ссылки изображений и аудио. Финалы считаются по всему графу, включая недостижимые; отсутствие исходящих переходов означает финал. Достижимость учитывает линейные и межсценовые переходы, но игнорирует значения переменных и условия.

Недостижимые узлы и узлы, где каждый выбор имеет условия, выводятся как предупреждения для автора и не делают сценарий невалидным. Условные варианты могут совместно покрывать все игровые состояния; статический отчёт этого не доказывает. Проверьте маршруты вручную или отдельными тестами, обеспечьте доступный выход в каждом достижимом состоянии. Функция не изменяет сценарий и не усиливает runtime-валидацию.

Для проверки самого анализа:

```shell
./gradlew :shared:testAndroidHostTest --tests '*StoryAnalysisTest'
```
